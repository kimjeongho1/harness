# score_check — 잊기 쉬운 점수 행동 알림
사용자는 작업 중에 아래 항목을 잊을 수 있다. **사용자가 묻지 않아도** 정해진 순간에 짧게 알린다. 대신 해 주지 않는다. 담당자 대화와 판단은 사용자가 한다.

## 점검 항목 (기록에서 찾는다: DECISIONS, git log, HANDOFF)
| 항목 | 있으면 | 찾는 법 |
|---|---|---|
| S1 담당자 1차(사실) 질문과 답 | D-0 존재 | DECISIONS |
| S2 담당자에게 선택지를 보여 주고 고르게 한 기록 | 근거에 "담당자 선택" | DECISIONS |
| S3 **AI 제안을 거절·축소한 기록** | "AI 제안 수정" 행 또는 `refactor: … 제거` 커밋 | DECISIONS, git log |
| S4 **담당자에게 결과를 보여 주고 받은 피드백** | 근거에 "결과 확인" | DECISIONS |
| S5 미검증 공개 | HANDOFF 검증 표에 NOT_RUN 포함 여부 | HANDOFF |
| S6 약점·아키텍처 설명 준비 | 마무리 노트 | record 5번 |

## 알림 시점과 형식
- **STATE·RECORD 때마다**: 마지막 줄에 `점수 체크: S1✅ S2✅ S3❌ S4❌ …` 한 줄. ❌가 있으면 지금 할 수 있는 가장 쉬운 행동 1개만 제안.
- **L1 커밋 직후 (A)**: "지금 담당자에게 결과를 보여 줄 때입니다(S4)." + 아래 '결과 확인 문장' 초안.
- **기능 결과 보고 때 (A)**: "요구에 없는 것·빼도 되는 것: …" 한 줄. 후보가 있으면 "빼면 S3 기록이 됩니다".
- **동결 직전 (C)**: S1~S6 표 전체 + 서술형 준비 노트 생성(record 5번).

## 결과 확인 문장 초안 (S4) — 열린 "어때요?" 금지
```
[결과] 말씀하신 <기준 D-n> 기준으로 돌려 보니 <핵심 숫자 2~3개>가 나옵니다.
[예시] 예를 들어 <구체 사례 1개>는 <이렇게> 처리됩니다.
[확인] <발견한 애매한 지점>이 있는데, A(<영향>)와 B(<영향>) 중 실제 업무에 맞는 쪽은 어디인가요?
[빠진 것] 이 결과로 실제 업무를 할 때 빠진 게 있을까요?
```
담당자 답은 사용자가 C에게 "기록해: 결과 확인 …"으로 전달한다.
