# data_to_db — CSV → DB
출처: ripplelover cofa-ready-kit `data-contract`(MIT)의 "행의 의미 먼저" 아이디어 반영.

1. **프로파일**(코드로): 파일별 행 수, 열, 추정 타입, 결측, 중복, 키 후보, 파일 간 연결 열 후보. 표 하나로.
2. **행의 의미 확정**: 파일마다 "한 행 = 무엇 하나"를 한 문장으로. 키가 무엇인지, 같은 대상이 여러 행이면 왜인지(이력? 중복?). 모르면 `[사용자 결정 필요]`.
3. **설계 논의(코드 금지)**: 테이블·PK·FK·NOT NULL·UNIQUE, CSV 열 → 테이블 열 매핑 표. 바뀌는 데이터는 덮어쓰기 vs 이력 테이블 장단점. DB는 기본 SQLite(요구가 다르면 요구를 따름) + 이유. 사용자 선택 후 진행.
4. **스키마·적재**: `db/schema.sql` + 적재 스크립트. 재실행해도 같은 결과(멱등). 거부 행은 사유와 함께 리포트(파일별 읽음/적재/거부/사유별 건수).
5. **검증**(SQL로): 테이블 행 수 = CSV 행 수 − 거부 수, FK 위반 0, 업무 규칙 확인 → PASS/FAIL. 사용자에게 손으로 대조할 2건을 골라 준다.
6. **기록**: 이상치 처리(이유·영향 건수·전후)는 INBOX에 "D-n | …" 한 줄로. 커밋 `feat(db): 적재 N행, 거부 M행, FK 검사 PASS`.
